# Genomic computation landscape

The biological source of an analogy and the novelty of its software translation are separate questions. No genome tuple is adopted as the book's axiom.

| Biological property | Candidate abstraction | Closest existing idea | What would justify retaining the analogy? |
| --- | --- | --- | --- |
| Context-dependent regulation | Select computation conditional on state | Routing, MoE, dispatch | Better selection under a measured constraint, not simply a gate |
| Development | Construct executable structure from a compact description | Program synthesis, neural cellular automata | Generalizable construction under environmental change |
| Modular reuse | Persistent library of composable operations | Software modules, DreamCoder libraries | Measured transfer or search benefit over ordinary libraries |
| Regulatory memory | Multiple state/write regimes | RNN state, external stores, continual learning | Explicit retention and update advantage |
| Mutation and selection | Propose structural edits, evaluate populations | Genetic programming, NAS, evolution strategies | Useful search bias with matched evaluation budget |
| Repair and homeostasis | Restore behavior after perturbation | Fault tolerance, adaptive control | Measured recovery and bounded intervention |
| Expression traces | Record actual activated computation | Execution logs, profiling, causal tracing | Better structural credit assignment than these controls |

Relevant starting sources: [source register](primary-sources.md), especially E-S04, E-S06–E-S09. Biological mechanisms still need chapter-level primary citations. The strongest default explanation is ordinary conditional computation with biological names. The program must defeat that explanation experimentally or use ordinary names.
